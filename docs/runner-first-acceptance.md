# 破风：运动员优先的产品验收与 16 张参考截图整改（2026-11）

本文件是来自用户真实 iPhone 体验的**阻塞级产品验收要求**。目前尚未全部实现。不要拿自动化测试通过或设计样板来代替用户验收。

## 产品定位

一款让跑者每天愿意打开的中文 App。三个高频任务：**看今天的课表、开始记录跑步、添加一顿餐食**。首屏不应像企业管理后台，不应有大量英文小字、折叠栏和表单。

## 基础使用路径和点击预算

1. 初次设置：选项目 → PB（可跳过）→ 训练组（可改）→ 立即展示**完整一周课表**。不能自动弹键盘，不要求比赛日期、跑量或恢复问卷。
2. 日常训练：首页直接看到今日训练 + 本周横向日期卡；一键打开完整课次，包括热身、主训练、恢复间歇、放松与训练目的。
3. 食物添加：营养 → 搜索/拍照/扫码/历史 → 调整份量 → 保存；不应出现连续多次二次确认。
4. 跑步：开始 → GPS / 手动 / 文件导入 → 记录与报告；必须区分 Web 前台和原生后台能力。

### 针对先前 16 张 Norg 参考图的结构映射

- 今日训练 Hero → **今日跑步课次**，紧凑但专业；图片/动效原创，禁用未授权素材。
- 训练 / 饮食切换 → 快速进入营养，保持当日上下文。
- 计划封面及横向卡 → 专项和组别浏览；入门、基础、进阶、竞技及各项目分类。
- 全屏训练详情 → 单次课次按模块展示训练结构；解释只在展开时显示。
- 训练动作列表 → 跑步热身、主训练组、组间恢复、冷身；健身力量训练作为可选配套。
- 身体数据卡 → 跑步数据（PB、周训练、配速/分段、睡眠与恢复），不把体重或热量当默认中心。
- 趋势详情 Bottom Sheet → 时间范围切换与点值查看，可拖拽关闭，不被键盘遮挡。
- 餐食记录与营养弹层 → 早餐/午餐/晚餐/加餐；拍照识别后允许纠错。
- 训练课程市场 → 多专项、有训练基础分层的原创课程；展示实际课程结构而不只是一行名称。
- 成就/段位/排行榜 → 个人进步和自愿参与，真实数据分级验证，青少年默认隐藏位置与身份。
- 主题 → 原创轻量主题，不复制 Norg 角色图、商城素材和他人内容。

## 核心专业性：训练引擎不得机械套模板

- 支持 800m、1500m、3000m、5km、10km、越野、半马、全马。真实分类应对应训练目标与阶段，而不仅仅换标题。
- 少量经审核的**训练组**共享周期结构，再按个体背景和训练响应做适度调整；PB 只用于初步推断比赛专项能力，不足以判断近期训练承受力。
- **健康竞技跑者**不自动获得零基础跑走计划；**受伤运动员**也不能因旧 PB 高就直接获得高负荷训练。已报告疼痛时保留专业评估及安全门槛。
- 首页只显示今日主要课次，但**默认展开一周分组训练结构**，不能让用户误以为整个竞技计划只有 15 分钟慢跑。
- 训练课次必须展示：名称、目的、结构、适用训练组、相对强度、恢复安排。没有合法或可信来源时不要编造精确配速数字。
- 国际资料来源保持可追溯，分清论文、官方教练教材、公开教练案例和未经证实经验；不能把收录数量当训练质量。
- 课表数据要审核运动员年龄、训练负荷与疼痛风险；避免将一个成人精英计划直接套用给青少年。

## UI / UX：让眼睛舒服、让手指少点

- 默认 4–5 个主导航目标，训练、跑步开始和饮食记录高频入口明显。
- 主视觉只突出今日训练，不重复罗列同一数据。次级高级解释折叠。
- 不用长篇英文装饰标题；中文短句，留白、轻量卡片、清晰文本层级。
- 原创摄影或获得商业授权的视觉素材；不复制 Norg 的人物角色、logo、独特卡面。
- 动画：日期左右滑、课程横滑、卡片自然展开、进度图一次性绘入、Modal/Sheet 自然转场、按钮按压反馈；可减少动态效果且没有持续炫光。
- **键盘避让**：打开 PB 弹窗时不能自动弹出软键盘。用户点击 PB 后，表单应仍可滚动，所有按钮可见，关闭或完成后弹窗状态正常；需要真实 iPhone Safari 测试。
- iPhone 安全区、横向滚动卡、触控尺寸及文字缩放通过真实截图验收。

## 营养产品：学习薄荷健康的便捷流程，而不是复制内容

- 添加餐食：食物搜索、份量、餐次选择、保存；历史、收藏、组合餐、扫码和 AI 照片为快捷入口。
- 使用合法数据库并记录来源，不能照搬薄荷专有食物库或其源码/界面素材。
- AI 估算显示不确定性，用户确认后才保存，不能声称照片能精确计算营养含量。
- 青少年模式突出充分进食、运动补给和恢复；不使用热量亏空、减重奖励、食物抵扣或不适宜的身体比较。

## 排行榜与会员

- 成就、段位、个人进步优先于单纯追逐跑量；榜单需用户自愿加入，区分官方成绩、设备记录和手输未认证。
- 不泄露青少年学校、具体路线、实时位置和健康数据；提供退出、屏蔽、举报/更正机制。
- 免费版完整覆盖记录与基础训练；会员可提供经审核的高级计划、深度分析和 AI 辅助，但不提前擅自收费。

## 硬性验收（最少）

1. iPhone Safari 真机：PB Sheet 打开**不弹键盘**，点击输入后按钮无遮挡、可保存。
2. 800m PB 2:20 / 进阶和 1500m PB 4:55 / 竞技：完整周结构与训练详情明显非入门版本；若近期仍疼，暂停相应训练建议。
3. 零基础跑者和已康复进阶跑者：计划层次明显不同，但都有合理恢复。
4. 训练页首屏 3 秒能看懂今天练什么，3 次交互以内查看周课表和课程详情。
5. 手机首页无水平溢出，底部导航没有被系统安全区遮挡。
6. 餐食搜索 → 份量 → 保存实际数据一致；拍照结果需人工确认。
7. 准备真实 iPhone 的前后对比截图/录屏，并注明设备及构建版本。
8. npm test + 浏览器测试 + iOS 构建检查：必须附**真实执行日志**，不能声明未运行的检查通过。

## 代码与发布规则

- 现有仓库与 PR 链必须保留，先核对祖先分支，不盲目合并。
- PR 使用独立分支且不覆盖其他在开发的文件。低风险的 UI 改动可自动进行；原生权限、生产发布、付费服务仍需用户授权。
- 当前 GitHub 可见性为 Public，必须审查商业资产、敏感数据与 API 密钥；用户曾要求私有。
- 所有发布需注明「Web 测试」或「原生真机」，不能混淆。
- 优先修正实际体验，而不是让功能数量或测试数量成为目标。
