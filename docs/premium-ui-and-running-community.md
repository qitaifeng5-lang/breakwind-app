# 破风 BREAKWIND — 16 张参考图的原创产品与 UI 落地规范

状态：**设计与工程验收规范，非功能完成声明**  
目标分支：`feat/premium-runner-ui-foundation`  
产品定位：中文优先的跑步训练 / 运动记录 / 恢复 / 营养 / 日程 / 社区应用。

## 0. 设计立场

参考图来自一款健身 App，参考的是 **内容层级、动态大卡、底部抽屉、训练细节、图表钻取、计划市场和社交激励**；不复制原 App 的品牌、角色图、商店素材、页面截图、独特美术或源码。

现有应用已具有训练周期、前台 Web GPS、手动与文件导入、餐食记录、iOS 原生定位开发版等能力。此次改造**不删除任何有效业务逻辑**，先修视觉，再逐个接真实业务流。

跑者首屏优先：今日训练 → 开始跑步 → 本周里程与恢复。体重和热量只是用户主动选择时的可选信息，而不是默认的中心指标。

## 2. 原创界面的信息架构

底部主导航：**今日、训练、记录、数据、我的**。  
日程和营养可以通过「今日」显著入口及「记录」快捷操作到达，避免底部塞满 7–8 个菜单。桌面端使用适配布局，但优先手机。

### 今日页

1. 顶部：破风品牌、日期、通知、设备连接状态。
2. 今日训练 Hero：摄影底图仅用于氛围，半透明强对比文本层；有计划展示结构，无计划展示创建入口。
3. 本周「运动表现」：跑量、训练次数、训练负荷反馈，距目标的进度为可选信息。
4. 训练日历/下一节课。
5. 营养与恢复简明摘要，点击进入详情。
6. 今日洞察：必须附依据，绝不编造训练数据。

### 训练页

- 顶部搜索与专项筛选；横向计划封面；计划详情完整页面。
- 训练计划页包括训练周期、适用能力、每周频次、科学来源、训练结构、恢复/调整条件。
- 单次课次按热身 / 主训练 / 恢复 / 放松分段；可展开、完成、编辑并保存。
- 开始跑步：手机 GPS / 手表导入 / 手动记录选择，不能伪造设备已连接。
- 完成页：路线、配速、分段、心率（如有）、恢复反馈，数据来源明确。

### 营养页

- 早餐、午餐、晚餐、加餐。搜索、扫码、拍照（AI 估算）、历史、收藏、自定义。
- 日期切换与营养图表 bottom sheet；照片识别用户必须确认并可修改。
- 成年人与青少年视图遵循不同健康规则；青少年重点关注**营养充足、规律进餐、训练补给与恢复**。
- 不使用「热量缺口」「剩余额度」「消耗抵扣」作为青少年默认 UI。

### 数据页

- 里程、配速、PB、训练分布、完成率、睡眠、恢复、营养记录。
- 卡片 → 局部底部抽屉 → 按天/周/月切换。图表可触摸查看点值，提供文本数据表替代。
- 没有数据时使用真实空状态，不显示虚构趋势。

## 3. 排行榜与社交：优先数据安全

### 榜单类别

- 官方赛事：800m / 1500m / 3000m / 5km / 10km / 半马 / 全马。
- 好友与跑团：训练坚持、个人进步、经过确认的活动参与。
- 跑量榜仅作为明确的**可选**频道，并强调恢复和安全，不以无限增量为主要激励。

### 成绩验证模型

`verified_official`（官方赛事链接与审核）  
`device_recorded`（具数据来源的运动记录，不等于官方认证）  
`manual_unverified`（人工输入未验证）

必须在界面显示验证等级，不应把设备数据与官方成绩混排为同等真实性。

### 反作弊和隐私

- 默认不参加公开榜单，参加前主动同意；退出可移除公开信息。
- 青少年默认不公开真实姓名、精确地理位置、训练路线、学校、生日和敏感健康数据。
- 城市榜仅使用用户主动选取的泛化城市；不使用实时地理位置做精确排名。
- 排行榜数据的审核、举报、申诉、屏蔽、删除与更正流程需要设计。
- 先做本地可交互示例，再开发后端权限、验证、审核；不能用假数据假装线上实时排行榜。
- 成就奖励个人进步、适当恢复和长期训练一致性，避免高负荷、断食或忍痛训练导向。

## 4. 动效系统（不是靠持续发光）

| 交互 | 时长与反馈 | 限制 |
| --- | --- | --- |
| 页面进入 | 180–280ms，轻微淡入 + 上移 | 只在真正切页触发 |
| Hero 图 | 非交互微弱缩放 / 手势视差，低频 | 不造成眩晕，不遮住文字 |
| 主按钮 | 120–180ms 轻微缩放与阴影 | 反馈清晰，不能误触 |
| 数据图表 | 250–650ms 的一次性出现与选中反馈 | 不自动循环；数据变化时重绘 |
| Bottom Sheet | 230–330ms，底部弹入 + 遮罩 | 支持下滑、关闭按钮、Esc 与焦点恢复 |
| 计划横滑 | 惯性与吸附，保持滚动位置 | 不自动无限轮播 |
| 跑步开始 | 短确认反馈后进入高可读的实时仪表盘 | 运动中禁用复杂视觉负担 |

尊重系统 Reduce Motion；低电量与低性能设备应自动降低视觉成本。移动端优先合成层属性 `transform` / `opacity`，避免大面积 blur 和每帧 JS 重排。

## 5. 视觉规范与组件

- 黑背景 `#0C0D10`、表面 `#14151A` / `#1A1B20`、品牌红 `#E63742`。
- 文本根据数据层级，绝不都用相同 14px 字号。
- 主视觉大数字在 30–48px 范围根据屏幕适配；公里分段数据使用 tabular nums。
- 触控控件至少符合合理的移动触控目标，标签必须可被辅助技术识别。
- 图片：原创摄影/获得许可的运动照片，不使用参考截图中的人物或其他未经许可内容。
- 原生 iPhone 的 status bar、安全区域、键盘避让与底部标签栏需真机验证。
- 建立 `PerformanceHero`、`RunPlanCarousel`、`WorkoutBlock`、`TrainingChart`、`NutritionSummary`、`DetailSheet`、`Achievements`、`RankingBoard`、`ThemePicker` 等可复用组件。
- 当前 Web CSS 只完成一轮视觉增强，之后把新设计组件落到 Web 和原生两端，避免两套产品风格漂移。

## 6. 交付顺序与验收门槛

### P0：可见且可用的 UI 纵切

- 今日页动态训练 Hero、可操作训练与营养切换。
- 训练计划发现/详情/展开课次，真实业务数据连接。
- 数据卡 → 底部详情弹层，日/周/月切换与真实数据。
- 统一组件与基础动效；无数据及错误状态。
- 截图对比 iPhone 375 / 390 / 430 CSS 像素视口与桌面 1280 / 1440。

### P1：营养流程

- 餐食按日期展示、食物搜索、份量调整、历史、收藏、组合餐。
- AI 照片识别流程中的加载/估计/纠错/无结果。
- 营养趋势 bottom sheet，与保存数据一致。

### P2：跑者成长生态

- 个人纪录、训练成就、原创计划发现页与主题选择。
- **本地演示** 排行榜：必须永久显示「示例」字样，不暗示真实用户竞争。
- 完成后端安全、官方成绩校验、审核与隐私评估后，才可以上线公开榜。

### 验收报告模板

每一阶段必须提供：
1. 本次修改的文件和对应页面；
2. 手机真机/模拟器或浏览器截图，注明来源；
3. 点击路径（从首页开始，几步可以完成任务）；
4. 有实际执行记录的测试结果；
5. 未实现项和明确限制；
6. GitHub PR、是否已合并，以及真实可用的预览链接。

**不可用图片代替工作代码，不可把尚未实现的功能勾为已完成。**
