# iPhone 真机验收记录

原生验收使用经过签名的 Expo development build 和真实 iPhone。网页 GPS 与浏览器视口测试独立记录。

## 准备

- 在支持 Expo SDK 56 的 Mac / Xcode 环境执行 npm ci，再通过 npm run mobile:ios 安装到启用开发者模式的 iPhone。
- 分两次安装。先用默认 GPS 构建；然后用 BREAKWIND_HEALTHKIT=1 重新生成并签名安装包含 HealthKit entitlement 的构建。
- 每次记录 Git SHA、iPhone 型号、iOS 版本和构建编号。报告只记录是否通过、误差范围和故障分类。不要附上真实路线、位置坐标、健康记录或账户标识。

| 验收项 | 操作与通过条件 |
| --- | --- |
| 授权边界 | 分别尝试拒绝、仅允许使用期间、关闭精确位置以及始终授权。前三种必须说明原因且不能显示后台记录已启动。 |
| 锁屏与长时运行 | 在开阔、熟悉且有标记的路线连续运行至少 15 分钟，其中至少 10 分钟锁屏。解锁后时长与轨迹连续递增，后台运行记录可保存。对比另一台设备的总距离与耗时，记录偏差和失点。 |
| 停止定位 | 跑步中暂停并移动约两分钟，再恢复。暂停时长与移动不可计入，恢复后路线应分段。结束后确认系统定位指示停止。 |
| 中断恢复 | 在跑步中切换飞行模式、撤销定位权限并模拟进程退出。回到应用后应明确显示状态，并保留此前样本。强退期间不能伪造采样或计时。 |
| HealthKit | 授权后导入一条已知跑步，再导入相同记录。来源应可辨认，第二次不增加记录。分别验证拒绝与系统撤销权限后的反馈。 |
| 电量与发热 | 分别记录同一手机的空闲基线和一次 30 分钟锁屏跑步。记录起止电量和是否发热；出现明显耗电或系统终止时，记为待排查。 |

所有项通过并记录后再评审原生 PR。移动端网页可通过独立 HTTPS 地址验收，不影响上述签名和设备要求。
